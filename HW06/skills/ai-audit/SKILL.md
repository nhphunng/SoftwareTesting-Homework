# AI Audit Skill — HW06 API Testing

## Purpose

Use this skill for every significant AI-assisted step in HW06 so the final AI Audit Report can be built from real interaction records instead of reconstructed history.

The assignment requires each AI interaction to retain at least:

- AI tool name;
- date and time;
- task/stage;
- prompt;
- AI output;
- affected artifacts;
- human decision;
- corrections;
- final result.

This skill is **evidence capture**, not evidence fabrication.

## When to activate

Activate this skill whenever AI materially contributes to any HW06 artifact or decision, including:

- API/specification analysis;
- API selection or verification;
- domain partition design;
- state-transition analysis;
- security analysis;
- schema analysis;
- AI-generated test cases;
- test-case audit support;
- Postman/Newman scripting assistance;
- failure/bug analysis;
- CI/CD assistance;
- AI-driven test-generator design;
- report/critique assistance.

Do not create an audit interaction for trivial navigation or shell-only operations where AI produced no meaningful project content.

## Interaction lifecycle

### 1. RECORD

Immediately after a meaningful AI interaction, record the original interaction before editing its content into the project.

Required fields:

```text
Tool
Date/time
Stage
API scope
Prompt
AI output
Artifacts affected
```

The original prompt and AI output must remain traceable.

Initial human decision may be:

```text
PENDING
```

when the human has not reviewed the result yet.

### 2. HUMAN REVIEW

The student reviews the AI result and chooses exactly one:

```text
ACCEPT
MODIFY
REJECT
```

Meaning:

- `ACCEPT` — result is correct enough to use without substantive correction.
- `MODIFY` — useful result, but student corrected or refined it.
- `REJECT` — result is not used because it is wrong, unsupported, unsafe, duplicated, or irrelevant.

Every `MODIFY` or `REJECT` decision must have a reason.

### 3. CORRECTION / FINAL RESULT

When AI output is modified, preserve both:

```text
Original AI Output
→ Human Review
→ Human Correction
→ Final Artifact / Result
```

Never replace the original AI output with the corrected version.

## Classification of contribution

Use one of these labels when relevant:

```text
AI-GENERATED
AI-ASSISTED
HUMAN-CREATED
EXECUTION-EVIDENCE
```

Definitions:

- `AI-GENERATED`: AI produced the candidate content directly.
- `AI-ASSISTED`: AI helped analyze/review, but human created or substantially transformed the final content.
- `HUMAN-CREATED`: student-created content; AI may only have been used later for review.
- `EXECUTION-EVIDENCE`: real output from Postman/Newman/GitHub Actions/SUT execution; never claim this was generated by AI.

## Integrity rules

1. **Append; do not rewrite history.**
   - Existing interaction records must not be silently rewritten to make the workflow look cleaner.
   - Later human review is appended as a review addendum when necessary.

2. **Preserve original prompt.**
   - Do not polish or shorten the prompt after the fact.

3. **Preserve meaningful AI output.**
   - Keep enough output to reconstruct what AI proposed.
   - If output is very large, store it in a referenced artifact and record the exact path.

4. **Never fabricate timestamps or interactions.**
   - Record only real interactions that occurred.

5. **Never fabricate execution evidence.**
   - Newman output, Postman console evidence, screenshots, GitHub Actions runs, and SUT responses must come from real execution.

6. **Human review is mandatory.**
   - Final AI-generated test cases must not remain `PENDING` before submission.

7. **Trace artifacts.**
   - Record every file materially created or changed as a result of the interaction.

8. **Keep rejected AI output.**
   - A rejected result is useful audit evidence and must not be deleted merely because it was wrong.

## Logger usage

Record an interaction using files for prompt/output when possible:

```bash
python3 skills/ai-audit/scripts/append_audit.py record \
  --tool "ChatGPT" \
  --stage "API1-DOMAIN" \
  --api "PoolA-FR-05-ProductSearch" \
  --contribution "AI-GENERATED" \
  --prompt-file /tmp/prompt.txt \
  --output-file /tmp/output.txt \
  --artifact "PoolA-FR-05-ProductSearch/analysis/domain-partitions.md"
```

Append human review later:

```bash
python3 skills/ai-audit/scripts/append_audit.py review \
  --id AI-001 \
  --decision MODIFY \
  --reason "AI inferred an unsupported keyword length boundary." \
  --changes "Removed unsupported boundary and marked it UNRESOLVED pending specification evidence." \
  --final-result "Accepted after correction."
```

## Final report preparation

Before submission:

1. Verify every significant interaction is indexed in `ai-audit/audit-log.md`.
2. Resolve all material `PENDING` human reviews.
3. Use the interaction records as the source for `ai-audit/AI-Audit-Report.md`.
4. Do not invent missing historical prompts/output.
5. Cross-check audit entries against Git history and final artifacts.
